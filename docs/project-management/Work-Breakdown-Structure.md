# WBS Notes

## WBS Level Definitions

**Level 1 — Project**

The entire Yek Flashcards project.

**Level 2 — Major Deliverable/Workstream**

Major areas of project work such as Project Management, Product Requirements, UX/UI, Content, Development, Testing, and Launch.

**Level 3 — Work Package**

A meaningful body of work that can be planned, estimated, assigned, and tracked.

**Level 4 — Activity**

A sufficiently specific activity that can be converted into Jira Stories, Tasks, or Subtasks when appropriate.

---

## Relationship to Jira

The WBS is **not intended to replace the Jira Product Backlog**.

The WBS provides the high-level decomposition of the project, while Jira provides the detailed execution and Sprint management structure.

The relationship should generally be:

**WBS**

→ Major deliverable

→ Work package

→ **Jira Epic**

→ **Jira Story**

→ **Jira Task/Subtask**

For example:

**5.2 Farsi Audio**

→ **5.2.2 Record Farsi vocabulary**

→ Jira Epic/Story structure

→ Individual recording tasks

→ Individual QA tasks

The exact Jira mapping does not need to be one-to-one for every WBS item.

---

## WBS Scope Boundary

The WBS intentionally includes both:

1. **Product development work**, and
2. **Project-management/portfolio work**

because Yek Flashcards has two simultaneous purposes:

- To create a functional language-learning application
- To demonstrate the planning, execution, monitoring, and management of a real software project

Project-management documentation is therefore considered legitimate project work rather than merely administrative activity.

---

## WBS Maintenance

The WBS should be treated as a relatively stable project-planning artifact.

Changes to individual implementation tasks should generally be managed through Jira rather than constantly modifying the WBS.

Major scope changes—such as adding a major new language, fundamentally changing the monetization model, or adding a major new product capability—may require WBS updates.
